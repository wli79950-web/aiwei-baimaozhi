# 制作流程细则（开工、渲染、交付时读）

沿用自「艾唯说挖洞」已验证的流程（2026-11-26 用户确认全部沿用），按白帽志的视觉系统改写。

## 工作流程
- **剪辑思路先行**：拿到完整脚本后、出分镜图之前，先交一份「剪辑思路 + 生图清单」汇报，用户确认一次再往下做（用户说「直接做」则跳过）。汇报内容：
  1. 整期理解：这期讲什么，观众看完要带走的一两句干货；结构怎么切（开场钩子、章节、收尾）。
  2. 逐段剪辑思路（一段一行的表格）：对应口播 → 难点（听得懂 / 抽象需演示）→ 画面怎么讲（录屏推镜、语句拆解、图解、实物比喻、金句卡、人物画面）→ 上屏什么字、标在哪 → 用哪个场景（A 炭黑 / B 奶油白）、哪个排版、哪些信息卡、配哪张贴纸。
  3. 重点标记：最需要花力气的地方（最抽象的原理、金句、反转），以及需要用户拍板的地方。
  4. 生图素材清单（见下一条），附在汇报后面。
- **素材规划先行**：拆分镜和做 AE 包之前，先逐镜头规划生图素材：
  - 数量按「契合口播、不抢核心演示」范围内的**最大量**规划；实操录屏、人物画面不加图。
  - 每张标「类别」：1 实物贴纸（口播说到的东西：`real`，全期 1–2 个高光用 `anime`，手机用 `device`）· 2 意象插画（要让观众意会的意思：先写「要传达的意思」，`sc02-line` → 模切贴纸）· 3 氛围装饰（`ambient`，每屏 ≤ 3）。素材尽量透明底。
  - 清单按 `docs/templates/生图清单模板.md` 写明：总数、每张用在哪个镜头、对应哪句口播、文件名、完整提示词；确认后用 `tools/genimg_list.py` 生成 `tools/genimg.py` 的任务文件。
  - 用户确认（可删减、改提示词）后再生图；不合格的重生，最多 3 次。用户自己生图交来时逐张核对，不符合或缺的超过 3 张列出来让用户补，3 张以内自己生成。
- 渲染 MP4 之前，先给用户看分镜图（附手机竖屏模拟图），确认后再渲染。
- 分镜那一步同时交付 AE 包，见 `docs/rules/AE包规范.md`。
- 风格或版式大改时，先出几张排版关键帧给用户看，确认后再做全片。
- 用户说「直接做」时，跳过所有确认环节，直接渲染。
- 局部修改只重渲受影响的片段，替换进原片，不要整片重做（工程按片段组织、保留中间产物）。
- 用户问进度时，说清楚做到哪一步、下一步做什么。

## 视频输出规格
- 只出横屏 1920×1080（本仓库暂不出竖屏），60fps，导出 MP4。
- 视频时长与口播音频严格一致；画面元素按口播逐句、逐字卡点。
- 交付的成片要能直接使用；分成多段制作的内容必须合成一条连续视频。

## 模型检查（硬规则，详细步骤）
- 模型必须是 Opus 5.5（claude-opus-5-5）。
- 每个大步骤开始前（读文案 / 拆分镜、出分镜图、生成素材、渲染片段、合成成片、局部重渲），先调用 `get_session`（不传 session_id），检查 `session_context.model` 和 `external_metadata.last_served_model`。
- 只要其中任何一个不是 claude-opus-5-5，就立即停下，告诉用户当前是哪个模型、停在哪一步、已完成的产物在哪里，等用户切回模型或明确指示后再继续。
- 用户可以临时指定其他模型，照做并在交付和提交记录里注明哪些步骤用了哪个模型。

## 每期收尾
- 在 `EPISODES.md` 记录期号、主题、时长、用过的排版 / 信息卡 / 素材；提交并推送。
- **`main` 只保留最新两期的工程**（`episodes/` 下最多两期）。第三期合进 `main` 时：
  1. 在最旧那一期还在 `main` 上的最后一个提交打标签 `ep/<期号>`（例：`git tag ep/BM01 <提交> && git push origin ep/BM01`），整期工程随时可以从标签取回；
  2. 从 `main` 删除那一期的目录，在 `EPISODES.md` 的「归档」一栏写上标签名；
  3. `EPISODES.md` 的素材使用记录保留全部期数，用来核对「同一张生图不得出现在两期」。
- 口播原片、逐帧抠像、渲染中间产物放在各期的 `footage/`、`build/`、`out/`（不进 git）。
