# 录屏组件（P4 第二部分 · 网页端完成）

白帽志的核心讲法之一：**用户提供的录屏是证据**，配合标注、信息卡和贴纸，把「发生了什么」讲清楚。全新编写，不含 lieflat / 挖洞号代码。

| 文件 | 作用 |
|---|---|
| `screencast.css` | 窗口、视口、打码、标注、光标的样式（只用 tokens 变量） |
| `screencast.js` | 组件库（全局 `SC`）：`SC.shot` 搭镜头、`SC.render` 渲染一帧（async）、`SC.validate` 检查、`SC.keyframes` 给 P6 AE 生成器的关键帧数据 |
| `../../tools/make_demo_recording.js` | 生成一段**示意录屏**（页面标「教学示例」）给演示和自检用，输出到 `out/`，不进 git |
| `../../tools/screencast_check.js` | 自检 + 预览：`node tools/screencast_check.js`（加 `--video` 另渲染 6 秒样片） |

## 用法
```js
// 用户录屏先转成帧序列（Chromium 没有 H.264 解码，而且帧序列才能逐帧确定性地取到同一帧）：
//   ffmpeg -i 录屏.mp4 -vf fps=30 -q:v 2 episodes/BM01/footage/rec1/%05d.jpg
const bg = BGLIB.mount(section, 'BG1', 'libs/backgrounds/');
const h = SC.shot(section, {
  rect: [64, 56, 1792, 968],                                    // 窗口：画面宽 85–94%（和信息卡同框写 narrow: true，≥ 68%）
  src: { type: 'frames', url: 'footage/rec1/%05d.jpg', fps: 30, count: 412, w: 1920, h: 1080 },
  remap: [[0, 0], [2.6, 2.6], [6, 2.6]],                        // 时间重映射：两点原片秒相同 = 定格（可省）
  push: [{ at: 2.2, rect: [1110, 380, 780, 220], dur: 0.8 }],    // 推镜：把这块区域放大到视口里（留 10% 边距，原片不露边）
  ann: [{ type: 'mark', rect: [1140, 458, 300, 44], at: 3.05, label: '别人的订单', side: 'right', leader: true }],
  cursor: [{ at: 0.5, x: 700, y: 400 }, { at: 1.0, x: 560, y: 88, click: true }],
  mask: [{ rect: [1124, 300, 600, 40], mode: 'blur' }],          // 打码：token、手机号、真实域名
  links: [{ from: [84, 404, 560, 72], to: '.ic', at: 2.95 }],    // 联动：从录屏里一处拉引线到信息卡
  enter: { at: 0 }
}, { base: '' });
window.renderAt = async t => { BGLIB.animate(bg, t); await SC.render(h, t); };
```
坐标除了 `rect`（窗口在画面里的位置），都是**原片像素**；推镜时组件自动换算到屏幕上。

## 组件
| 组件 | 做什么 | 规则 |
|---|---|---|
| 窗口 | 炭灰窗口（B 场炭黑）+ 朱橙 / 奶油白三个圆点 + 圆角 36px 的视口；平放，不做 2.5D | 宽 85–94%；和信息卡同框 ≥ 68% |
| 原片 + 时间重映射 | 帧序列或单张截图；`remap` 分段线性，可慢放、定格 | 原片保留原色，不调色 |
| 推镜 | 聚焦区域留 10% 边距放进视口；全景顶对齐（地址栏不被裁掉）；缩放和位置按 P2 缓动插值 | 讲细节时可推到满视口 |
| 标注 | `mark` 朱橙圆角框（描线画出）· `underline` 下划线 · `spot` 聚光（其余压暗）；可带标签（朱橙块 + 炭黑字 52px）和引线 | **一个镜头同一时刻最多一处强调**（前一处写 `out`），`SC.validate` 会拦 |
| 光标 | 放大的箭头（奶油白 + 炭黑描边）+ 朱橙点击涟漪；在原片坐标里移动，推镜时跟着走，大小不变 | — |
| 打码 | `blur`：同一帧原片的模糊副本，裁到这块区域；`block`：炭灰斜纹块 | 全程都在；推镜放大后仍看不清（自检会量） |
| 联动 | 从录屏里的一处画朱橙引线（描线）连到画面上的信息卡 | 信息卡用 `cards/infocards/` |

标注线宽、标签字号、光标大小都在**屏幕坐标**里画：推镜放大时不会跟着变粗变大。

## 和 AE 的对应（P6 生成器照这张表做）
| 网页 | AE |
|---|---|
| `.sc-win`（窗口外框 + 标题栏） | 「窗口边框」图片层 |
| `.sc-view`（视口） | 「录屏窗口_镜头号」预合成，尺寸 = 视口 |
| 原片帧序列 + `remap` | 预合成里的录屏原片素材层 + 时间重映射关键帧（用户「替换素材」即可换录屏） |
| `.sc-cam` 的 `push` | 原片层的缩放 + 位置关键帧（位置拆分维度），缓动用 `ae/motion_ae.jsx`；`SC.keyframes(spec)` 直接给出每个关键帧的缩放和平移 |
| `mask`（blur / block） | 预合成里的调整层：高斯模糊 + 蒙版 / 斜纹形状层 |
| `ann` 标注框、下划线、聚光 | 形状层（修剪路径做描线） |
| 标注标签 | 文字层 + 圆角矩形形状层 |
| `cursor` | 光标图片层 + 位置关键帧；点击涟漪 = 椭圆形状层 |
| `links` 引线 | 主合成里的形状层（修剪路径） |

## 检查：`node tools/screencast_check.js`
- 纯数学 43 项：时间重映射（默认 / 定格 / 慢放）、帧号边界、全景铺满不露边、推镜后聚焦区域完整在视口里且原片不露边、推镜插值起止、光标插值、`validate` 拦得住「窗口太窄 / 同时两处强调 / 区域超出原片」。
- 3 个演示镜头在多个时间点检查：标签字号 ≥ 52、字色 / 底色（和信息卡共用 `tools/lib/pagecheck.js`）、逐帧确定性（最大差 ≤ 8 色阶记提醒）。
- **打码必须真的看不清**：在每个关键时间点（含推镜放大后）量打码区域的边缘能量，要低于同尺寸清晰文字的 25%（实测 3–12%）。故意关掉模糊时这一项会失败。

预览在 `docs/previews/screencast/`：`S1_1 / S1_2`（光标点地址栏 → 推镜 + 框选 + 标签 + 打码）、`S2`（下划线 + 联动引线 + 关键词卡 + 时间重映射定格）、`S3`（B 场 · 窄窗口 + 聚光 + 斜纹打码 + 清单卡）、`_mid`（过程中）、`phone.jpg`（手机竖屏模拟）、`screencast_demo.mp4`（S1 六秒样片，带运动模糊）。
